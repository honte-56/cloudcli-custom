Acknowledged ordinary sends — 2026-10-20
---------------------------------------
The composer now keeps drafts until chat.send or chat.edit-send receives a
chat_send_receipt from the gateway. Offline sends fail visibly; unconfirmed
sends show a spinner, retain input and attachments, and time out explicitly.
Reconnects retry the same request id. Session storage retains uncertain ids
through reloads; changing display-only session titles does not change identity.
Uploaded attachments are reused on retry. Late replies do not clear new typing
or append to a different open conversation.

The database chat_send_receipts table stores authenticated-user/session/request
keys, payload hashes and admission responses. Duplicate requests cannot restart
a completed turn, including after a server restart. Pending requests left by a
restart are reported as uncertain, never blindly executed. Accepted means the
gateway has reserved the run and is dispatching it, not that the model finished.
Older clients without requestId remain compatible; refresh to use confirmations.

2026-10-28: attachment limit and browser connection recovery
- Chat attachments now accept 100 MiB per file (previously 10 MiB). Picker,
  drag/drop and paste share validation, and rejected files display an error.
- Uploads larger than 8 MiB use authenticated, user-scoped chunks. Each request
  stays under the reverse proxy limit; completed files are streamed together.
  Retries reuse upload IDs and completed descriptors rather than duplicating
  attachments. Interrupted partial uploads expire after 24 hours, cleaned on
  subsequent upload activity. Each HTTP chunk has a two-minute deadline.
- Browser sockets now have a 10-second handshake deadline and a 15-second
  application heartbeat with a 10-second response deadline. Focus, page-show,
  network-online and visibility events probe or replace stale transports.
  Replacement does not wait for a dead connection's close handshake, and stale
  socket callbacks cannot overwrite current connection state. Receipt-based
  message admission and reconnect history synchronization remain enabled.
